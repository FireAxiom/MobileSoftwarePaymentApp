Open the project in Android Studio and press ▶ Run. On the login screen, any email and password works.

**Try:** Groups → Cabin weekend → View balances → Pay a partial amount.

## The big picture (in 4 lines)

1. **Screens** are just functions that draw things (`@Composable fun GroupsScreen(...)`).
2. **Routes** are the screens' names/addresses (`"groups"`, `"group/g1"`).
3. **The NavHost** is a list of "route → screen". It shows one screen at a time and remembers history so Back works.
4. **The ViewModel** holds all the data. Screens read from it and call its functions.

```
MainActivity
 └─ AppNavHost  (Scaffold with the bottom tab bar + NavHost)
     ├─ auth graph:  01 Start · 02 Log in · 03 Sign up        (no tabs)
     └─ main graph:  04 Notifications · 05 Groups · 25 Profile (tabs)
                     + every other screen
```

Compared to React Native:

| React Native | Here |
|---|---|
| component | `@Composable` function |
| `<Stack.Navigator>` | `NavHost` |
| `navigation.navigate("X")` | `nav.navigate("x")` |
| `navigation.goBack()` | `nav.popBackStack()` |
| `<Tab.Navigator>` | `BottomBar` inside a `Scaffold` |
| Context / Redux | `AppViewModel` |
| `npm install` | a line in `app/build.gradle.kts` |

## Rules we follow

- **Screens don't navigate by themselves.** A screen only says *"Save was clicked"*
  (`onSaved = ...`). `MainGraph.kt` decides where that goes. To change the flow, edit
  `MainGraph.kt` and leave the screens alone.
- **Pop-ups aren't screens.** 10 (invite) and 14–17 (amount, payer, split, receipt) are
  bottom sheets. A variable decides whether they are open, so they have no routes.
- **"Return → 07" means going back, not forward.** We pop the history back to the
  group (`backToGroup`) so the group screen doesn't get stacked twice.
- **One form, two uses.** 13 Add and 19 Edit share one screen, and so do 21 Full and 22 Partial payment.
- **The offline banner is shared.** Every screen passes
  `offline = vm.offlineState(message = "...")`. It shows only when offline, always directly under the header.

## Reusable components (`ui/components/`)

| Component | What it is |
|---|---|
| `AppScreen` | Standard page: top bar → offline banner → scrollable content. Almost every screen uses it. |
| `BottomBar` + `Tab` | The 3 bottom tabs |
| `TopBar` | Title, back arrow, optional "Edit"/"Cancel" |
| `OfflineBanner` | Amber "Offline · Changes pending / Last synced" box |
| `OverlaySheet` | Bottom-sheet pop-up used by 10 and 14–17 |
| `PrimaryButton` / `SecondaryButton` / `DangerButton` | Black / outlined / red buttons |
| `ClickableRow`, `SwitchRow`, `CheckboxRow`, `LabelValue` | List rows |
| `AppTextField`, `GroupCard`, `Placeholder` | Input, group card, grey image box |

## What's done vs. not yet

**Done:**
- All 25 numbered screens and overlays, with every route and return from the navigation model.
- Bottom tabs.
- Balances math.
- Admin-only remove member and delete group.
- "Leave group" blocked while you have a balance.
- "Settle balances before deleting account".
- Remind member bell.
- Simulated offline mode with a sync notification.

**Not yet (on purpose):**
- Real login and backend.
- Saving data between app restarts.
- Real camera and receipt images.
- Forgot password and Manage invites. These have no screens in the model.
- Loading and error states for 05 (last row of the wireframes).
- Uneven splits.

To connect a real backend later, change the insides of the functions in
`AppViewModel.kt`. The screens shouldn't need to change.
